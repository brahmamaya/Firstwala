PHYSICA - NETLIFY-READY STATIC WEBSITE

DEPLOY
1. Extract this ZIP. index.html must be directly inside the extracted folder.
2. Open Netlify Drop (https://app.netlify.com/drop) and sign in if requested.
3. Drag the extracted folder containing index.html into Netlify.
No build command, backend, database, API keys, or environment variables are needed.
The ZIP itself can also be used by deployment tools that accept ZIP archives.

BUILD: index.html loads physica-core.min.js (sync) and physica.min.js (defer); physica-3d.min.js (detailed
3D scenes + Ultra scenes) is fetched after the page is up (lazy.js), and sw.js caches files for instant repeat visits.
from the readable source files by: node tools/build.js  (needs esbuild). Edit the sources, then rebuild.
ULTRA SCENES: ultra3d.js holds hand-built Ultra-Realistic scenes (window.PhysicaUltraScenes[id]); first: gravity-depth.
MATH: mathtext.js shows _ and ^ as real subscripts/superscripts on the page and in canvas drawings.
FOCUS: less important panels are compact and have a close (x) button; hidden ones return from the
"Hidden:" chips; the Focus button shows only the stage and controls (Esc exits) - focus.js.
TEACHER (tutor-teacher-content.js): offline adaptive teacher - replies in English, Hinglish or Hindi (follows the student),

TUTOR: Normal / Student / Teacher modes, chosen as step 3 on the landing page (tutor.js). Normal: unchanged. Teacher: projector view.
VOICE + CHAT: tutor asks the student's name once (kept only in this browser, physica-learner) and uses it now and then; a language picker (Auto/English/Hinglish/हिंदी) fixes the reply language; speech mood (happy/calm/soft) changes pitch, pace and volume. tutor-speech.js picks the most natural female voice on the device (Edge/Windows "Natural" neural voices first; nothing is recorded or shipped). Speech is split into short phrases with human-like pauses. tutor.js answers small talk (greetings by time of day, kaise ho, khana khaya, kahan ho...), does a daily "how are you feeling" check-in, and tells "Did you know?" facts (facts in tutor-teacher-content.js) when a student is bored or asks.
LEARNING LOOP: questions the tutor cannot answer are sent anonymously (deduped, max 20/day, 20 s apart) to the feedback Google Form: name "Tutor question", country "subject | chapter | sim | lang | level", text = question. tools/tutor-questions.gs (Apps Script inside the form, web app "Only myself") downloads a private CSV of questions since the last download, chapter-wise with dates. Answers go into tutor-learned.js ([question, keywords, answer] per chapter), then rebuild.
Student: an "AI Tutor" switch in the top bar turns the tutor on. It covers every physics chapter (tutor-chapters.js) plus automatic
"what does this control do" answers and demos built from each simulation. Chat (tutor-speech.js + tutor.js): a conversation with typing bubbles; the tutor asks back (predict first, quick checks);
numbers in a question are calculated with the simulation ("what if angle is 60"), "increase/double X" is worked out, other
questions are matched across all chapters with "did you mean"; female voice, physics read naturally. Ask by typing or voice, answers read aloud, Predict → Show me demos, spoken quiz (browser speech; no AI service).

SHARING AND STORAGE
Save stores up to 30 worlds in your current browser, not in a cloud account.
Share / Export creates a snapshot link or a .physica.json file.
Friends open a link or use Import file. Imported worlds open paused for editing.
Create share links on your published Netlify domain, not the preview domain.
Large worlds should be sent as files. JSON world files are limited to 250 KB.
Browser data is separate for each domain. Export any preview saves before moving
sites. An exported file is the safest backup. Clearing browser storage removes
local favourites and saves.

SANDBOX MODEL
100 world pixels = 1 metre; fixed 10 m by 6.5 m world, up to 150 objects and
200 connections. Springs use solver stiffness, rods keep a fixed distance.
Charge/attractor forces are illustrative, not calibrated electromagnetism.
Speed is limited to approximately 24 m/s for numerical stability; high-speed
collisions are approximate. Objects without boundaries stop beyond 50 m.
All scene changes can be undone (last 50 edits); continuous playback is not
recorded by undo. Reset run restores the start of the latest Play session.
Use Pause for precise placement, then select an object to edit its properties.

TECHNICAL
Plain HTML, CSS and JavaScript. physica3d.js is a small built-in 3D renderer
(perspective, depth sorting, lighting, orbit camera) with no external libraries;
labkit.js and seventh.js to tenth.js hold the 100 newer 3D physics experiments;
phys3d-a.js to phys3d-d.js give the 176 original physics experiments their 3D scenes
(instruments2d.js: hands-on vernier caliper and screw gauge with drag, contact and magnifier);
(optics2d.js: hands-on Ray Optics, 12 sims: drag candle, laser, coin, prism, lenses, eyepiece on a real optical bench);
biokit.js and bio1.js to bio5.js hold the 100 biology experiments.
Matter.js 0.20.0 and its MIT licence are included
locally in vendor/. No external scripts or CDN dependency. No React build is
needed for this archive. Use a current Chrome, Safari, Firefox or Edge browser.

LEAN BUILD (node tools/build.js does all of this every time):
1. tools/optimize-css.js - cascade-aware dead-code eliminator for styles.css. A declaration is removed only when,
   for every selector in its rule, a later declaration of the same property for the exact same selector exists
   with equal or higher !important, in a context that is always active when the earlier one is (top level or the
   same @media/@supports chain). Same selector = same specificity, later wins, so the earlier one can never apply.
   Intra-rule fallbacks and anything overridden by color-mix()/dvh values are kept; duplicate @keyframes keep the last.
   Running it twice changes nothing. Verified by comparing every element's computed style before/after in 62 states.
2. styles.css is then minified to styles.min.css (that is what index.html loads).
3. The AI Tutor's lessons and notes (tutor-content, tutor-chapters, tutor-teacher-content, tutor-learned) are a
   separate physica-tutor.min.js, downloaded only when a student turns the tutor on (tutor.js loadTutorPack()).
   Normal and Teacher mode never download it. The 3D pack (physica-3d.min.js) loads on idle as before.
4. Botany/Zoology (bio1-5.js) and Chemistry (chem1-4.js) are their own packs: physica-bio.min.js and
   physica-chem.min.js. tools/subject-manifest.js runs those files once at build time in a sandbox and keeps only
   their plain data (id, title, description, chapter, controls) as a small index inside physica.min.js, so the
   library, search, counts and shared links work before the packs arrive. The packs load on idle after the page is
   up, at once when a subject tab is pressed, or immediately for a direct link; until then the stage says
   "Loading…". When a pack lands, labkit.js pack().done() fills in the placeholders and fires 'physica-pack'.
   biokit.js stays in the main bundle because some physics scenes draw its human figure.
5. Smoothness rules in app.js: a paused simulation is redrawn only while something can change it (window.PhysicaWake),
   drawing never runs faster than ~60 fps, and it stops while the stage is off-screen.
6. Big boards (75-86 inch, 4K) and Teacher mode use the "lite" look: same colours, but no glass blur and softer
   canvas glows. They still draw at 60 fps; the stage resolution follows the measured frame time (GPU included),
   changes (on non-4K screens) only after a slowdown or headroom that lasts a few seconds, and backs off if it keeps flipping. 30 fps is
   only the last resort. On 4K boards (BIG) sharpness comes first: a slow frame never lowers the stage resolution
   there (30 fps is the fallback instead), and the canvas uses the device pixel ratio up to 2x.
   The landing black hole ray-traces at about 4.2 MP on 4K-size screens and frees its GPU memory once the landing
   page closes (big GPU allocations can leave parts of the page unpainted on tablets/boards).
   iPhone/iPad (WebKit) get html.noblur: no live backdrop blur anywhere (Safari left parts of the sidebar and the
   controls card unpainted with many blur layers); same colours, solid glass backing for what floats over content.
