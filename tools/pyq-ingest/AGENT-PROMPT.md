# Prompt for a transcription agent (paste, then add the batch file path)

You write PYQ entries for Physica Rank mode. Work ONLY on the batch file named below; do not open anything else except what this prompt says. Do not scan the repo.

1. Open the batch file. For each question open ONLY its crop PNG (Read tool). The OCR text in the batch is a rough hint; maths in it is often wrong - trust the crop.
2. Write one JSON object per line into `entries-NN.jsonl` in the same folder (NN = the batch number): `{"pn":<PDF question number>,"y":"<exam and year as printed, e.g. JEE Main 2025 · 2 Apr · Shift 2>","tp":"<topic id>","st":"<sub-topic>","q":"<question, plain text, unicode maths, \n for new lines>","o":["...","...","...","..."],"c":<index or [indices]>,"s":"<solution written by you, short, step per line>"}`. Numerical: `"n":<number>` instead of `o`/`c`. Multi-part or match-the-column: put the lists inside `q`, answer in `o`/`c` as in the existing files. Use the topic ids of the chapter file (ask the caller if none given).
3. Key: the batch shows the PDF key. If your own solving gives a different answer, keep your answer, start `s` with `Note: the printed key says X; working gives Y`, and mention it in your final report. Never skip a question because it is hard.
4. Diagram: if the batch says `YES`, or the crop really has a diagram, add `"fig":{...}` as a PhysicaFig spec (draw original art; look at `rank-figs.js` for the spec types, never copy the publisher's picture). If it only says `drawing-like` and the crop is just a formula, no fig.
5. NEVER invent or 'restore from the usual paper' any text, option, graph or number. Each question has one crop and sometimes a second crop ('continues here, read it too'). If after reading both the stem, an option or a figure is still missing or unreadable, do not write the entry: write the line {"pn":<n>,"gap":"what is missing"} into the jsonl instead and list it in your report; the owner or the caller will supply it. A numerical question whose crop shows no options is numerical only if the text asks for a number.
5a. Keep each question in its ORIGINAL form. Multi-part (a)(b)(c), subjective, True/False or fill-in-the-blank questions are NOT turned into numerical or option questions: put the whole text in `q`, no `o`/`c`/`n`, and give the full answer text in `a` (e.g. {"pn":124,...,"q":"...(a)...(b)...","a":"(a) 5×10⁷ (b) 2×10³ N/C"}). True/False may use o:['True','False'].
5b. A crop that "ALSO HOLDS Q<n>": write both entries from that crop. A question marked "may continue": check the next crop.
6. Solutions are your own words (no copying of the book's solution text). Keep them short.
7. Final report (3 lines): number of entries written, questions with a fig, key disagreements (numbers).

## Maths chapters (read this too when the chapter is Maths)
- Solution style (`s`): write it STEP BY STEP for students aged 15-18, one numbered step per line: `Step 1: ...`, `Step 2: ...` ... and a last line `Answer: ...`. Each step is one short idea in simple words and says what is done and why (for example "Step 2: A relation is reflexive when (a, a) is in R for every a, so check (1, 1), (2, 2), (3, 3)."). Show the working (substitutions, counting, the small table) instead of jumping to the result; name the formula or property used. Typically 4 to 8 steps; more only if the question needs it. Never just copy the book's solution: re-derive and explain in your own words.
- Question text is plain unicode (no LaTeX): ∈ ∉ ⊂ ⊆ ∪ ∩ ∅ ℝ ℕ ℤ ℚ → ⇒ ⇔ ≠ ≤ ≥ √ ² ³ ⁿ and fractions as (a)/(b); the greatest integer function as [x]. Use plain braces for sets inside q/o/s (the fullwidth ｛ ｝ rule applies only to the chapter-content file, not here). Numerical-answer questions (answer is an integer) are `n`. Questions with several correct options use c:[i,j].
- For 'Sets, Relations and Functions': tp must be one of sets, rel, func, dr; st exactly one of: sets: 'Sets and their operations' | 'Venn diagrams and counting' | 'Power set and subsets'; rel: 'Types of relations' | 'Equivalence relations' | 'Counting relations'; func: 'One-one and onto functions' | 'Counting functions' | 'Composition and inverse' | 'Functional equations'; dr: 'Domain and range' | 'Even, odd and periodic functions' | 'Greatest integer and fractional part'.
- Verify by computation: for every counting/numerical question (relations, functions, sets) run a quick brute-force in node (in /tmp) before you write the answer; if your answer differs from the printed key, keep yours and start `s` with `Note: the printed key says X; working gives Y`.
