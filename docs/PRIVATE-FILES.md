# Keeping private files private

The repository `brahmamaya/Firstwala` is **public**, and so is everything on the live site (GitHub Pages cannot hide files).

| Material | Where it lives | Never |
|---|---|---|
| Your source question banks (`content/`), figures before export, drafts | your own computer or a separate **private** repository | in this repository (`content/`, `build/`, `private/` are git-ignored and blocked by `tools/private-guard.js`) |
| Public test files (free tests 1-3 only) | `tests/` (generated by `tools/series-import.js static`) | anything paid or unreleased |
| Passwords, tokens, API keys | a password manager / GitHub Secrets | any file in the repo (`tools/secret-guard.js` blocks the build) |

Automatic guards: `.gitignore`; `tools/secret-guard.js`; `tools/private-guard.js` (tracked private paths, huge data files, anything outside the public whitelist); `tools/publish.js` whitelist (only `*.min.js`, HTML, fonts, icons and `tests/` go online); `tools/lockdown.js` 404 rules; the watchdog checks that `.env`, `.git`, `tools/`, `docs/` are not readable on the live site.

If something private was ever committed, deleting it is **not enough**: treat it as leaked (rotate the secret / replace the paper) and then clean the history.
