# Lessons (the tools and the way of working improve from real jobs)

Rule: at the end of every task ask "did a tool, an agent or my own method misbehave?". If yes: (1) fix the tool so it cannot happen again, (2) add a regression test (or a check that prints a warning), (3) add one line here (date, what went wrong, what changed). At the start of a task of a known kind, grep this file for the keyword (pdf, agent, merge, bundle ...).

- NEET paper PDF: Chromium JPEG pages of text+figures are ~170 KB each even at 1x; 1.5x gave 16 MB. Keep scale 1 and quality .72 unless a vector PDF writer is added.
- Paper download as Word: makeDocx in rank-export.js (zip of WordprocessingML, no library); checked with python-docx and LibreOffice (63 pages for 2026 with solutions).
- Download speed: measured on 69 pages with 4x CPU throttle, drawing is ~25 ms/page but JPEG encoding ~260 ms/page, so encoding is the cost. Now encoded in a worker pool (enc-worker.js -> physica-enc.min.js, falls back to toBlob), one reused page canvas, pictures decoded in parallel, paper + PDF code prefetched when a year is chosen. In the sandbox the gain was small (sol PDF 3.0 s -> 2.6 s); phones with more free cores should gain more; measure before promising numbers.
- Word papers: docx-ingest.js (zip + XML + OMML, no dependency) tested by round-tripping our own makeDocx output; a Word list numbered (1)-(n) inside a stem looks like options, so the LAST (1)-(4) group is taken as options; answer text containing digits or '*' (e.g. '(3) σ*2p') must not be read as labels; a run of underscores is a blank, never a subscript.
- Word prompt for ChatGPT saved in docs/WORD-PROMPT.md (matches what docx-ingest.js reads); the owner sends the paper PDF to ChatGPT and gives the .docx to the assistant.
- Paper PDF was blurry on zoom, 6-11 MB and not copyable because pages were JPEG images; rewritten as a vector PDF (ttf.js + pdf-vec.js, fonts/pp-*.ttf): 180/335 KB, ~0.3 s, selectable text. Esbuild turns `()=>({...})` around a build token into a block: put build tokens inside a call (`JSON.parse(__TOKEN__)`).
- PYQ slide PDF/PPT: draw slides with the vector writer (copyable text) and use real sub/superscript runs; e2e must go back to the chooser before clicking a subject pill.
- tests/ is public: private-guard now fails on any tests/ file outside the free index (n<=3); a paid test copied by hand can no longer ship.
- Local chapter tagger (naive Bayes on the 180 NEET 2026 questions) was tried 2026-11-05: leave-one-out only 30% right (46% when 'sure'), so it was NOT kept. Revisit only when 1500+ tagged questions exist (about 8 more papers). Tagging, solution rewrite and diagrams need a model; everything else (read file, checks, assemble) is already code.
- NEET 2025 (answers+solutions PDF, image-only): biology booklet order is mixed (no Botany/Zoology headings), so subject comes from the chapter; agents given the 2026 order wrote wrong sub values and '?' chapters (fixed in the merge). Blind figure check found 14 of 29 physics figures with label/curve faults (one path typo) vs 0 of 26 chemistry: always run the figure verifier. Paper labelled 'NEET 2026' earlier is Re-NEET 2026; relabel before adding the real NEET 2026.
- NEET chapter pages waited on the network for every tap because prefetchPyq() skipped NEET (X.nk); it now fetches the ready chapters of the open subject on idle (questions show in ~20 ms).
- NEET 2026 (3 May, text PDF with solutions): the PDF has a text layer, but maths is image fragments, so page images stay the master for formulas; the text layer is used for plain words. A question can be misnumbered in the source (Q.64 printed for Q86): reconcile by sequence. Figure verifiers found 3 fixes in 49 figures (clipped label, missing angle, a solution picture stored as a question picture).
- A paper cost ~2-3 M agent tokens (measured): fixed overhead per 4-page agent, 12-17 agents at once hit the 5-hour limit twice (work repeated), extra checking passes, strongest model, and a huge conversation. Rules are in docs/CREDIT-SAVING.md; tools/pyq-ingest/textcheck.js checks printed keys for free on single-column text PDFs.
- textcheck.js now uses pdftotext -layout (the default order detached Q numbers from their text) and has --min (word coverage) and --sol n (numbers in our solution that the printed block lacks). NEET 2024: 191/200 questions agree with the independent text layer on every plain word, number and key; only 89 of 200 (flagged + figure + maths-like) need an agent look.
- NEET 2024 paper PDF failed ('Could not make the file') because 3 text items of the Q44 solution figure had a null option: destructuring defaults only cover undefined. pdf-vec.js now treats null as none (regression in tools/pdf-vec.test.js) and the e2e step 'chapters told apart' no longer needs a Soon chapter (every Physics chapter now has questions). ALWAYS download the new year's paper in the browser before merging a year.
